## Scope

Reproduce and resolve the three reported live-site contrast findings without changing the established brand, then add a regression check to the repository's existing gate.

## Baseline observations

Measured in Chrome at a 1280px viewport against the live site:

| Finding | Observation | Resolution direction |
| --- | --- | --- |
| Services “What's included” | `rgb(123,123,134)` on white, 11.52px, **4.184:1** | Genuine WCAG AA failure for normal text. Use the existing light-surface secondary token only in paper offer sections. |
| “oblivion” | 92px meaningful text in the home-page `h1`; transparent text fill exposes the animated spectrum background. The accessibility tree announced the complete heading, “Your admin, automated into oblivion.” | Intentional and accessible. Do not hide it or replace its colour. |
| Empty 17.44px spans | Three 26×2px hamburger strokes, white on white according to a text-only colour sampler. They contain no text and the button is named “Open menu”. | Decorative. Explicitly hide each stroke from assistive technology. |

The same offer labels on black measured **5.020:1**, so changing `--faint` globally would alter passing uses and was rejected.

## Implementation

- Added `.on-paper .offer__includes h3 { color: var(--faint-dark); }`. This reuses the established light-surface semantic token and leaves dark sections unchanged.
- Added `aria-hidden="true"` to the three hamburger strokes. The containing button keeps its accessible name and state.
- Added `tests/contrast.test.ts` to calculate WCAG contrast from the emitted production CSS for both light and dark offer sections.
- Extended `tests/a11y.test.ts` to prevent the hamburger decoration becoming exposed again.
